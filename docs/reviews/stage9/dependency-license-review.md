# Stage 9 Dependency and License Review

Review date: 2026-07-26  
Review baseline: `76f5624e664c556c3ec598055524319eab0af1f3`  
Review owner: Platform / Security  
Legal status: technical inventory only; not legal advice  
Publication decision: **NO-GO**

## Result

The 19-image release inventory is complete and integrity-pinned. Go module
verification, npm lockfile inspection, source-build pins, image SBOM generation,
Trivy scanning, and release-manifest validation provide a reproducible technical
inventory.

Publication is blocked because:

1. the repository has no approved distribution license;
2. complete per-binary third-party notice/source-offer obligations have not been
   approved and packaged;
3. Grafana, Loki, and Tempo are AGPL-3.0;
4. Xray-core is MPL-2.0;
5. Redis 8 is tri-licensed under AGPL-3.0, SSPL-1.0, or RSALv2 and the production
   license choice is not approved;
6. a professional review has not concluded whether the intended deployment,
   registry publication, and any image distribution satisfy those obligations.

No image may be published while `deploy/release/license-policy.json` says
`NO-GO`. The policy validator intentionally distinguishes a truthful review
check from the strict publication gate.

## Reviewed inputs

- `go.mod`/`go.sum`: 18 direct module requirements and the complete module graph
  returned by `go list -mod=readonly -m all`.
- `package-lock.json`: 169 locked npm packages; declared license identifiers are
  limited to 0BSD, Apache-2.0, BSD-2-Clause, BSD-3-Clause, BlueOak-1.0.0, MIT,
  and Python-2.0.
- `deploy/release/images.json`: 19 production images; two fake-provider images
  are explicitly classified as local-only.
- per-image SPDX 2.3 SBOM and Trivy JSON generated by digest-pinned Syft 1.44.0
  and Trivy 0.72.0.
- source archive SHA-256, release commit, patched dependency pins, copied
  LICENSE/NOTICE files, and OCI labels in custom observability/Xray Dockerfiles.
- commit-pinned GitHub Actions in both workflows.
- tracked asset scan: no repository-owned font, WOFF/TTF/OTF, bitmap, or bundled
  UI asset exists outside upstream Grafana/Prometheus source images.

SPDX is evidence, not a legal conclusion. `NOASSERTION`, `NONE`, `LicenseRef-*`,
unknown expressions, or an expression absent from the exact allowlist block
publication until reviewed.

## Security rebuilds and VEX

Prometheus, Grafana, OpenTelemetry Collector, Tempo, Loki, and Xray are built
from version/commit/SHA-pinned sources. Dependency changes are explicit in their
Dockerfiles. Tempo has one exact-PURL OpenVEX statement for the reviewed
Prometheus LTS patch and a build assertion that the sensitive field uses the
redacting type. The VEX statement is not a general license or vulnerability
waiver and must be re-reviewed on source, dependency, route, or patch change.

## Checks

`make license-review-check` validates exact correspondence between the release
inventory and machine-readable policy and requires `NO-GO` while any image is
blocked or requires counsel.

`make license-publication-gate RELEASE_OUTPUT_DIR=<bundle>` additionally
requires an overall `GO`, every image approved, every SBOM present, and exact
allowlisted license assertions for every package. It is expected to fail at this
review baseline. It must not be added to a green deployment path by weakening
the allowlist.
